## 教训（反复出现，写新 validator 前先过这张表）

1. **英语形态学双词干**：不规则变形单词干必漏一支。perceiv/percep（forage）、freez/froz（本批：freezing 走 freez-，frozen/froze 走 froz-）。新增排除族时先过一遍变形表。
2. **elif 链吞噬副作用**：枚举/集合检查里 violation 分支与 append 副作用必须解耦（先 append 再单列 violation），否则 selftest 共启期望对不上。forage R1 与本批各中两次。
3. **守卫会在自己的工件上开火**：状态用语与守卫词撞车时改工件措辞、不改词表放行（not frozen→not final, not binding）；中文技术词含关键词单字时同理（拓扑 含「扑」→改「结构」；表达成本 含「成本」→表达开销，forage F6）。README §2 洁净声明必须能对 config+dsl 全文 grep 机械复验。
4. **selftest 先跑再交付**：本批自测首轮 3 FAIL 全是真实实现缺陷；期望用例写严格（共启族精确 set 相等）才有拦截力。
5. **表格单元格禁竖线**：`\|` 转义在自研 naive 表格解析（与多数 md 消费者）下仍拆列，行宽检查必炸——单元格内枚举写「A/B」或「A 或 B」，不用竖线。grazing 批首轮真实校验 4 缺陷中 2 个即此（另 2 个是正文散文里的 @伪 token——先例引用不写 @ 符号，@ 前缀留给真绑定并全部入清单）。
6. **CANON 列名先 norm 再比**：表头比较前双方都要过同一 norm（去空白）；CANON 字面量直接写成 norm 后形态（「QualityTemplate」非「Quality Template」），否则族检查静默失效或全批误报。
