# RF4 / Fishing Planet 中鱼机制调研报告（证据审计版）

**调研日期：** 2026-09-01  
**范围：** 公开资料、官方指南/公告、开发者答复、可重复的社区观察；不进行客户端破解、抓包或违反服务条款的逆向。

## 1. 执行摘要

未找到 RF4（Russian Fishing 4）或 Fishing Planet 的公开源代码、服务端公式或完整概率表。因此，本报告不声称还原“真实代码”，而是把公开证据整理成可检验的机制模型。

两款游戏都应理解为多阶段流程，而不是一次随机抽签：

```text
水域/鱼群状态 → 鱼进入有效范围 → 试探或追踪 → 攻击/吞饵
→ 玩家刺鱼 → 挂钩 → 遛鱼张力判定 → 成功抄鱼或脱钩
```

RF4的公开资料（其中关键的两阶段描述来自非官方转载，当前官方正文/版本尚未核验）对浮漂咬口的“试探、吞饵”现象描述较明确；Fishing Planet的官方 Wiki 对鱼类 AI、环境变量、拟饵动作和线张力反馈描述更系统。两者的精确倍率、tick 周期、奖杯鱼抽样方式仍属未知。

## 2. 证据规则

### 2.1 来源优先级

1. 官方用户指南、官方 Wiki、开发者公告/答复；
2. 官方补丁说明与开发团队访谈；
3. 有样本量和控制变量的玩家实测；
4. 高质量攻略/数据表；
5. 单个经验帖（只作线索）。

### 2.2 结论等级

- **确定事实：** 官方明确说明，或多个独立实验稳定复现；
- **高可信推断：** 多条证据共同支持，但没有源码/公式；
- **待验证假设：** 单一来源、间接迹象或理论上合理。

## 3. 重点修订：等待时间与“会遇到什么鱼”

上一版对鼠标操作、钩子和线张力描述过多；这些属于鱼已经接触饵料后的结果层。本报告的核心现在改为“抛投后，鱼在什么时间尺度内、以什么条件进入候选集合”。

### 3.1 等待时间不是固定倒计时

没有找到官方资料证明“每 N 秒固定掷骰子”。更稳妥的模型是**时间变化的遭遇强度（hazard）**：

\[
P(\text{在 }\Delta t\text{ 内遭遇鱼})=1-e^{-\lambda(t,\,x,\,e,\,m)\Delta t}
\]

其中：

- `t`：抛投后时间及游戏内时段；
- `x`：抛投位置、水深、底部结构、水流和覆盖物；
- `e`：天气、温度、风、光照、季节；
- `m`：饵料/拟饵、深度、速度、停顿、抖动和轨迹。

这只是可解释的候选模型，不是两款游戏已公开的公式。它可表达部分现象，并可用于检验“长时间无反应时换点”与“继续等待”哪一种策略更有效，不能据此断言实际等待分布。

### 3.2 “会遇到什么鱼”应先于“是否咬钩”

研究上可把水域鱼表、钓点和水层作为候选鱼筛选器，但也保留“先改变活动强度、再由同一鱼表抽样”的竞争解释：

```text
水域鱼表
  → 钓点/地形/深度筛选
  → 当前时间、天气和活跃度筛选
  → 饵料/拟饵可识别性筛选
  → 鱼进入攻击范围
  → 试探、追踪或攻击
  → 吞饵与挂钩
```

Fishing Planet官方拟饵指南要求改变回收速度和深度来“寻找鱼”，并说明同一拟饵在不同深度可能完全不同；官方大鱼指南还明确把“速度 + 深度”视为物种条件的一部分。citeturn8search0turn8search5 RF4玩家的活跃钓点数据库也显示，地点、深度、饵料和鱼种是共同记录字段，但它是社区观测，不是内部鱼群表。citeturn8search2turn8search3

### 3.3 饵的姿态/手法是遭遇强度的一部分

对于拟饵：速度、深度、停顿、抽动、下沉/上浮轨迹和水流关系在本报告的研究者模型中共同决定 `λ`；这不是官方声称的参数名。Fishing Planet教程把 Straight、Stop&Go 等手法描述为模仿小鱼运动并提高捕食鱼攻击动机。citeturn8search1 对天然饵/浮漂/底钓，则把饵在水层中的位置、静止或漂移、气味扩散和喂食范围作为待检验变量，而非已证实的内部倍率。

### 3.4 等待策略的可检验指标

不要只统计最终鱼数，至少记录：

\[
\text{遭遇率}=\frac{\text{有效咬口或可识别攻击次数}}{\text{饵在水中分钟数}}
\]

按 0–10 秒、10–30 秒、30–60 秒、60 秒以上分桶，分别比较不同钓点、深度、时段、天气、饵和手法。若更换钓点后遭遇率显著上升，支持“空间候选鱼/活跃度”模型；若同一点等待时间呈明显峰值，才有理由讨论等待 hazard 的时间形状。

### 3.5 竞争机制假设（避免过早锁定单一算法）

| 假设 | 机制描述 | 能解释的现象 | 当前证据状态 |
|---|---|---|---|
| H1：连续遭遇强度 | 鱼持续在空间中移动，进入饵的有效半径时按时间变化强度触发 | 等待时间连续变化；换点改变遭遇率 | 高可信结构推断，非官方公式 |
| H2：抛投事件抽样 | 每次入水先按钓点/环境抽取候选鱼，再播放接近或咬口序列 | 同一次抛投的鱼种相对稳定；重新抛投可能重置结果 | 待验证 |
| H3：鱼群/热点状态 | 钓点有短时活跃度，鱼群迁移或被喂食吸引 | 连续中鱼、热点随时间移动、同点突然变冷 | RF4社区资料有线索；缺少公开参数 |
| H4：混合机制 | 先由地点和鱼群状态筛选，再用连续强度处理接近/攻击 | 同时解释地点差异和等待分布 | 当前最稳妥的工作模型 |

当前不选择 H1–H4 之外的“固定每 N 秒掷骰子”作为默认解释。若未来资料显示存在固定检查，也应视为实现细节，而不是把整个遭遇机制简化为单一随机数。

### 3.6 因素作用层归属

| 因素 | 主要可能影响 | 不应直接推断 |
|---|---|---|
| 水域鱼表 | 候选鱼集合 | 不能推出每条鱼已在玩家钩边 |
| 钓点/底部结构/草区/坑 | 候选鱼空间密度、接近路径 | 不能只凭“热点”推出固定刷新点 |
| 时间/季节/天气/温度 | 活跃度、迁移、摄食窗口 | 不能直接写成固定倍率 |
| 深度/水层/流速 | 鱼与饵的空间重叠 | 不能把错层解释成钩子问题 |
| 天然饵/地面饵 | 气味、扩散、停留和鱼群聚集 | 不能仅凭推荐饵证明概率公式 |
| 拟饵速度/停顿/抖动/轨迹 | 可识别性、跟随和攻击触发 | 不能把操作教程等同于内部参数 |
| 钩子/线张力/鼠标刺鱼 | 吞饵后的挂钩与脱钩 | 不应作为抛投后遭遇机制的核心解释 |

### 4.1 已确认事实

| 结论 | 等级 | 证据与含义 |
|---|---|---|
| 浮漂咬口有“试探→吞饵”两阶段 | 高可信推断（需版本核对） | 公开 Steam 攻略/用户指南转载描述：先出现不规则抖动，随后鱼带饵移动；应在第二阶段刺鱼。当前未取得可直接引用的官方正文，因此不升级为确定事实。 |
| 刺鱼要求线不能过度松弛 | 高可信推断（官方正文定位待核验） | RF4用户指南的公开转载版本描述松弛会吸收提竿动作；当前官方正文抓取不完整，故不标为确定事实。 |
| 鱼种具有不同谨慎度和咬口节奏 | 高可信推断 | 指南对鲫鱼、鲈鱼等咬口差异作了操作层描述，但未公布运行时参数。 |
| 发动机声音会影响胆小鱼 | 高可信推断（历史版本） | 2023-06-28 补丁镜像说明提高了胆小鱼对运行中发动机的警觉，并建议拖钓增加距离；仅证明该版本声明，当前版本是否仍适用未知。 |
| 钩子大小/类型/质量、竿角、张力、前导长度会影响脱钩 | 确定事实 | RF4开发者在 Steam 讨论中逐项列出这些因素。 |
| 深度、位置、饵料和喂食会改变咬口机会 | 高可信推断 | 用户指南、官方 FAQ 索引和长期玩家观察一致，但未给出权重。 |

### 3.2 浮漂状态机

```text
IDLE（无鱼）
  → APPROACH（鱼进入有效范围）
  → INSPECT（闻/看/试探，浮漂抖动）
  → SWALLOW（吞饵并移动，浮漂下沉/横移/躺倒）
  → HOOK_WINDOW（刺鱼窗口）
  → HOOKED 或 REJECTED
  → FIGHT / LOST
```

这里的状态机是对公开行为的建模，不是官方代码结构。其优势是能解释“有浮漂动作但提竿无鱼”：动作属于 `INSPECT`，尚未达到 `SWALLOW` 或钩子未进入有效挂钩条件。

### 3.3 RF4咬口因素的反推

可用以下结构表达，但不能填写未经实测的精确倍率：

\[
P(\text{bite})=f(鱼种基础活跃度, 时间, 天气, 水温, 深度, 地形, 饵料, 喂食, 线组隐蔽性, 噪声, 距离)
\]

\[
P(\text{hook})=g(吞饵阶段, 刺鱼时机, 线张力, 钩子, 前导, 鱼种口型)
\]

前导线体现明显权衡：更隐蔽可能提升谨慎鱼的接近/咬口，但更长或更软会降低传力、增加刺鱼或遛鱼风险。开发者答复还明确指出较长前导可能提高“鱼跑掉”的概率；这证明前导不只是外观参数。

### 3.4 RF4仍未知

- 咬口检查是固定 tick、连续时间 hazard，还是事件驱动；
- 地点疲劳是否存在、是否影响奖杯鱼；
- Trophy/Unique 是否独立抽样；
- 鱼是否始终以空间实体游动，或在投竿后按条件生成；
- 各鱼种隐蔽性、饵料和钩号的数值权重。

### 4.2 Fishing Planet状态机

饵钓/浮漂钓：

```text
FISH_POOL → IN_RANGE → RECOGNIZE_BAIT → NIBBLE/HOLD
→ SWALLOW → SET_HOOK → HOOKED → FIGHT/LOST
```

拟饵钓：

```text
LURE_IN_WATER → TRACK → CONTACT/STRIKE
→ SOFT_BITE 或 EFFECTIVE_HOOK → FIGHT/LOST
```

“追踪、轻碰、软咬、有效挂钩”是依据官方对鱼类 AI/拟饵动作的描述以及社区可复现实象建立的工作模型，不应写成官方状态名。

### 4.3 Fishing Planet咬口因素

\[
P(\text{approach})=f(地点鱼表, 鱼种活跃度, 时间, 天气, 水温, 水流, 深度, 地形, 饵/拟饵匹配)
\]

\[
P(\text{hook})=g(钩号, 饵料尺寸, 攻击角度, 刺鱼时机, 线张力, 钩型)
\]

钩号不是简单的“越大越好”：小钩覆盖更多小鱼，大钩偏向大鱼；过大可能只有轻微动作，过小则可能挂住但更易脱钩。但 Fishing Planet 0.3.0 历史更新明确放宽了钩号对鱼体尺寸的约束，并说明小钩也可能钓到 Unique；因此“钩号强筛选鱼体”只能作为旧版本或弱效因素，不能无版本泛化。官方资料给出了推荐范围，但没有公开当前版本每个偏离量对应的倍率。

## 7. 核心结论卡

### 等待时间

- **结论：** RF4官方手册描述等待阶段、重新抛投和不固定的吞饵窗口；Fishing Planet官方教程要求依据天气预报和 bite chart 选择高活跃时段。
- **证据等级：** 确定事实（存在等待/活跃度设计声明）；等待概率分布仍未知。
- **支持证据：** RF-06、FP-10。
- **反方意见：** 这些资料没有证明固定 tick、连续 hazard 或抛投后必然的时间曲线。
- **当前判断：** 等待时间应作为观测分布和策略问题研究，不应写成固定倒计时。
- **仍未知：** 入水后各时间段的真实遭遇率和是否存在初始触发窗口。

### 候选鱼遭遇

- **结论：** 水域、鱼种、习性、摄食地点和活跃时段共同决定“可能遇到什么鱼”；同种鱼在不同水域可能表现不同。
- **证据等级：** 确定事实（RF4官方手册设计声明）；内部鱼群实现未知。
- **支持证据：** RF-01/RF-06（官方本地化手册行号见附录）。
- **反方意见：** 设计声明不能证明鱼以持续空间实体存在，也不能证明候选鱼一定先于概率检查生成。
- **当前判断：** 先建立候选鱼集合，再保留“活动强度改变后抽样”的竞争模型。
- **仍未知：** 候选鱼是地点静态表、鱼群状态，还是抛投事件临时抽样。

### 钓点与水层

- **结论：** 水草、坑、洞穴、底部结构、水流和摄食深度是决定饵与鱼空间重叠的前置条件。
- **证据等级：** 确定事实（操作/设计层）；空间概率权重未知。
- **支持证据：** RF官方手册关于水草、底层和摄食深度；FP教程关于跳鱼、气泡、结构和深度。
- **反方意见：** “热点”也可能只是玩家选择偏差或预计算提示，不等于真实鱼群坐标。
- **当前判断：** 钓点应进入候选集合和可达性层，而非只作为咬口倍率。
- **仍未知：** 换点、重新抛投、改变深度分别重置哪些内部状态。

### 饵姿态与手法

- **结论：** 拟饵速度、停顿、抽动、下沉/上浮和水层会改变寻找、跟随和攻击机会；天然饵的静止/漂移和扩散范围仍需验证。
- **证据等级：** 高可信设计/操作推断。
- **支持证据：** FP-08/FP-09官方教程与拟饵指南；RF-06关于随流漂移和饵位。
- **反方意见：** 教程没有给出内部倍率，不能证明这些变量以独立参数进入运行时代码。
- **当前判断：** 将手法放在攻击前遭遇层，同时保留“只影响攻击而不影响候选鱼”的竞争解释。
- **仍未知：** 速度/动作改变的是鱼的位置、接近概率、攻击概率，还是多个层次。

### RF4 浮漂两阶段

- **结论：** 可观察到试探抖动与吞饵移动两个操作阶段。
- **证据等级：** 高可信推断（版本/来源待核验）。
- **支持证据：** RF-02 Steam 攻略整理的用户指南描述。
- **反方意见：** 当前未取得官方用户指南正文，且无带样本量的版本对照。
- **当前判断：** 可作为解释性状态机，不可写成已证实的内部类或公式。
- **仍未知：** 阶段时长、鱼种参数、当前版本是否变化。

### RF4 前导、钩子与脱钩

- **结论：** 钩子、前导、张力、竿角和线材会影响挂钩后的脱钩风险；隐蔽性与传力存在权衡。
- **证据等级：** 确定事实（开发者答复支持影响因素；倍率未知）。
- **支持证据：** RF-03 开发者逐项列出影响脱钩的因素。
- **反方意见：** 个案答复不等于全鱼种公式，长前导对咬口与脱钩的方向可能不同。
- **当前判断：** 将隐蔽、挂钩、遛鱼拆成独立层最稳妥。
- **仍未知：** 各材料和长度的具体权重。

### Fishing Planet AI 与环境

- **结论：** 官方把鱼种 AI、时间、天气、水温、水流、地形等列为行为设计因素。
- **证据等级：** 确定事实（设计声明）；运行时倍率未知。
- **支持证据：** FP-01、FP-02、FP-03。
- **反方意见：** Basic fishing tips 含现实科普，不能证明游戏实际使用同名传感器。
- **当前判断：** 可建立环境/鱼种状态层，不可反推出具体算法。
- **仍未知：** 环境因素是倍率、位置迁移，还是二者组合。

### Fishing Planet 钩号

- **结论：** 钩号和饵大小影响装备匹配与挂钩表现，但鱼体筛选效应受版本影响且并非绝对。
- **证据等级：** 高可信推断（版本限定）。
- **支持证据：** FP-05 推荐钩号；FP-06 v0.3.0 明确放宽钩号对尺寸影响，小钩可钓 Unique。
- **反方意见：** 旧攻略的“越大钩越大鱼”不能直接套用当前版本。
- **当前判断：** 只保留“尺寸偏向/弱效因素”表述。
- **仍未知：** 当前版本偏离推荐钩号时影响咬口还是挂钩，或两者都有。

### Fishing Planet Indicators 与线张力

- **结论：** 鱼钩进入鱼嘴后，线张力是保持挂钩和避免过载的关键反馈。
- **证据等级：** 确定事实（仅限挂钩后阶段）。
- **支持证据：** FP-04 Indicators；FP-07 Lines 对伸缩性和 hook-set 力度的说明。
- **反方意见：** 这些页面不证明初始咬口率或鱼种选择。
- **当前判断：** 单独建遛鱼/脱钩层，不把它混入 bite 概率。
- **仍未知：** 张力曲线、钩型和鱼种挣扎的精确关系。

| 维度 | RF4 | Fishing Planet |
|---|---|---|
| 最明确的公开机制 | 浮漂“试探→吞饵” | AI、环境变量、拟饵动作、Indicators |
| 咬口核心 | 警觉度、自然度、试探节奏 | 鱼种 AI、地点/天气、水层、拟饵行为 |
| 钩子作用 | 咬口、刺鱼、脱钩均受影响 | 尺寸偏向、咬口、挂钩和脱钩（版本相关） |
| 前导线 | 隐蔽性与传力/脱钩权衡突出 | 官方强调与饵料、钩号、目标鱼平衡 |
| 已公开精确公式 | 无 | 无 |

## 8. 可反推的通用实现

推荐把一次“中鱼”实现为三个独立随机层：

1. **接近/攻击层：** 从当前地点和环境中筛选可用鱼种，再计算接近或攻击机会；
2. **吞饵/挂钩层：** 根据鱼种行为、钩号、饵大小和刺鱼时机判定是否有效挂钩；
3. **遛鱼层：** 根据张力、竿角、装备强度和鱼的挣扎行为判定保持钩住或脱钩。

伪代码：

```text
fish = select_species(location, depth, season, time, weather)
if hazard(fish, bait, lure_motion, stealth, terrain) fires:
    state = species_bite_state(fish)
    if player_strikes(state, tension, hook, leader):
        state = HOOKED or REJECTED
while state == HOOKED:
    state = fight_step(tension, rod_angle, drag, fish_behavior)
```

该结构可表达部分公开现象，但尚未验证两款游戏内部是否采用该结构，更不能证明它们使用相同代码。

## 9. 可验证实验

### RF4

- 固定地点/时间/饵料，仅改变钩号；记录咬口、刺鱼、脱钩三种数量；
- 固定其他条件，仅比较前导材质和长度；
- 比较发动机开关、距离和抛投距离对谨慎鱼的单位时间咬口率；
- 对浮漂录像逐帧标记 `INSPECT` 与 `SWALLOW` 持续时间。

### Fishing Planet

- 固定地点/天气/时间，仅改变钩号；
- 仅改变浮漂深度，拟合咬口率随深度的曲线；
- 固定拟饵，仅改变速度、停顿和抽竿动作；
- 分别记录追踪、轻碰、软咬、有效挂钩，而非只记录最终鱼数。

每次实验必须记录版本、地点、玩法、装备、样本量和混杂因素。

## 10. 最终判断

公开证据支持“多因素 + 分阶段状态机”，不支持“一个固定间隔的单次随机抽签”这一简化说法。RF4的可见试探阶段更突出；Fishing Planet的环境与拟饵 AI描述更完整。任何具体倍率、刷新周期、奖杯独立概率或服务端实体架构，在没有额外数据前都应标为待验证假设。
